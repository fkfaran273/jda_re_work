**NEW — the fold is now EXACT (read off the raw ARM64, not inferred).**
`adj9/rev/fold_exact.py`:
- `0x144074 fold16(ctx,len,slot)`: `mask=(2*len+3)&0xffff`; **zero** the target
  `u16(ctx+0x30+2*slot)`; then for i=0..15, if bit i of mask set:
  `src=u16(ctx+0x10+2*(15-i))` (byte `0x2E-2i`, **word 23-i**); `acc ^= src`;
  store `acc` at the slot. Net effect = **one 16-bit write** =
  `XOR of the selected src words`. Acc starts 0 (`w2` is reset to `w3=0` at
  `0x1441cc`, NOT seeded with `slot` — the `slot` is only the write address).
- `0x143b20 search_slot(ctx)`: first i in 0..71 with
  `u16(ctx+0x30+2i) == u16(ctx+0xc0+2*(i&7))`, else 72. Confirmed.
- `0x1441e4` = `fold16(ctx,len,search_slot(ctx))`; `0x144214` =
  `for w in record_words: fold_word(ctx,w)` (`ldrh w1,[words+i*2]` → the record's
  16-bit LE words ARE the per-step `len`/mask).
- `ctx_init 0x1437ec` epilogue `0x143b0c`: `ctx[0xC0..0xD0] = ctx[0x30..0x40]` —
  the match table is a **frozen snapshot of the original words 0..7**. The 0x30
  region is later overwritten ⇒ search_slot becomes non-trivial. `ctx[0x10..0x30]`
