# 2026-09-11 — adj9: ctx/fold model DISPROVEN (decisive)

## Headline
The fold/ctx machinery (`0x143794` ctx_wrapper, `0x1437ec` ctx_init,
`0x143c88` shuffle16, `0x144074` fold16, `0x1441e4` fold_word, `0x144214`
driver) is **NOT in the signature path**. It is a separate subsystem
(almost certainly the obfuscated string/table decryptor — `fold_word` has ~47
callers, matching a string-decrypt sweep).

## Evidence (hard)
Built a **tight nSign burst** into the LSPosed module
(`Hook.java`: `BURST_ITERS = 40000`, loop of `callNSign(...)` on the
`adj9-oracle` thread, added right after `probe_start`). Rebuilt + installed.
Result:
- `burst_start ts=1789070775803 iters=40000 level=31`; no `burst_done` after
  7 min ⇒ ~10 ms/call (reflection + Xposed overhead), i.e. the burst ran for
  many minutes.
- Root-sampled the oracle thread (TID 17126, found via
  `grep -l adj9-oracle /proc/PID/task/*/comm`) **25 times** during the burst
  (`ctxburst` capture, 453 files / 479 MB).
- Byte-scanned every dump for the return addresses of the ctx path:
  `0xdb164`, `0x1437c8`, `0x1437bc`, `0x143794`, `0x143c88`, `0x144214`,
  `0x1441e4` ⇒ **0 hits each**.
- Anchor scan (16 u16 with unique high-bit positions = permutation 0..15,
  false-positive rate ~2^-92, scanner validated against a synthetic ctx)
  over **587 MB** (ctxsnap10, all rw-p ≤32 MB) and 479 MB (ctxburst)
  ⇒ **0 hits**.

## Consequence
- `get8random 0x13e0e4` (the only `/dev/urandom` reader reachable from
  ctx_wrapper) is never called during signing ⇒ the "one 32-bit urandom seed
  feeds the body" model is **wrong for the signature**.
- The per-call body randomisation is real and total: module oracle
  `probe_result` shows `A1~A2 (same in) n_diff=191` — two identical calls
  differ in 191/192 bytes (and even the 16-byte headers differ, since the two
  calls straddle a second boundary). So a per-call random source exists, but it
  is NOT this ctx.
- The real signing path leaves these return addresses on the oracle thread's
  stack (histogram of libsigner code ptrs, 25 dumps): `0xeefec` (x39),
  `0x7d9f4`, `0x8daa4`, `0x75a1c`, `0x708b8`, `0x705f8`, `0x6fc70`,
  `0x12f89c`, `0x13660c`, `0x136904`, `0x136b74`, `0x139608`, `0x139880`,
  `0x191ec4`. **These are the new lead** — start from `0xeefec`/`0x6fc70`.

## Method notes that now work (reusable)
- `toybox dd` does NOT accept hex `skip=` → use `printf %d 0x..` + `awk`
  (decimal only, awk has no 0x literals) + `iflag=skip_bytes`.
- Stack regions: `[anon:stack_and_tls:<TID>]` (pthreads) and `[stack]` (main);
  the `---p` guard page precedes each rw-p body — never read the guard page.
- libsigner.so is mapped straight from `split_config.arm64_v8a.apk` at offset
  `0x54000` ⇒ `libbase = text_start - 0x54000`; lib text seg is ~0x1490000.
- `/proc/PID/task/TID/stat` kstkesp is 0 on this kernel (no free stack ptr).
- `/proc/self/mem` is EACCES even for the app itself (SELinux) ⇒ in-process
  scans are dead; root `/proc/PID/mem` is the only way.
- Deterministic signing trigger: delete
  `/data/data/com.penti.app/files/AdjustIoActivityState` then launch ⇒ a fresh
  Adjust session ⇒ a genuine nSign within seconds (verified 8→10→14→16→26).
- Sampler loop bug to avoid: counting idle iterations in the pass counter makes
  the `MAXP` break fire the instant the app appears (only 1 real pass). Count
  only active passes.
