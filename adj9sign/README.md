# adj9sign — one-folder, one-click non-organic booking

Two files, pure Python, no device:

| file | what it is |
|---|---|
| `adj9_signer.py` | The WHOLE signature algorithm, self-contained: header law (bionic rand), region materializer (d0/d2/d4 from seed S), claims law (desc10), the FinEx VM interpreter, and the mint API. The three libsigner.so code spans it disassembles are embedded as base64 — no files needed beside it. Auto-generated by `_build_signer.py`. |
| `run_funnel.py` | The runner: put your **LINK**, **GAID** and **DEVICE_DATA** at the top, then `python run_funnel.py` — it fires the click and makes the three signed API calls (`/session`, `/sdk_click`, `/attribution`) and prints the verdict. |

## One click

```
pip install capstone curl-cffi
python run_funnel.py device.json        # ANY device-info dump -> auto-mapped
python run_funnel.py                    # or the built-in profiles
python run_funnel.py <gaid> [auid] [profile_name]
```

Takes ~1-3 min (three VM signings). Result is also saved to `funnel_result.json`.

**Dynamic mode (the normal way):** drop any device JSON dump next to the
script and pass its path. The mapper auto-extracts everything the tracker
needs — GAID (`adid`/`device_id`/`gps_adid`), model, build, os version,
api level, cpu, display, screen buckets, locale, the browser UA for the
click, and builds the matching Dalvik UA. Nothing about the signature is
per-device — only the device facts are. Optional keys in the JSON override
the synthesized ones: `gps_adid`, `android_uuid`, `installed_at`,
`updated_at`, `app_version` (otherwise installed_at = 7 days ago,
updated_at = 2 days ago — the re-attribution story).

> **Heads-up:** the tracker enforces a **20-minute minimum interval between
> sessions for the same device** — re-running sooner returns
> `400 request check interval failed` (with the exact remaining time in the
> error body). Space runs of the same GAID 20+ min apart; the re-attribution
> itself repeats indefinitely.

## What to put where (run_funnel.py CONFIG block)

- `LINK` — the tracker click link. `{adgroup}` is filled from `ADGROUP`
  (default `vkm_MMDD`); the winner proves the booked tracker carries OUR
  adgroup back.
- `GAID` — a REAL device advertising ID (harvest once via adb). This is the
  one input that must be real: the tracker only re-attributes devices it
  already knows. Empty → random-uuid control mode (works end-to-end, verdict
  comes back Organic).
- `ANDROID_UUID` — the device's android_uuid.
- `DEVICE_DATA` — the device fingerprint cloned from its own session capture.
  Keep `installed_at`/`updated_at` as the package-manager values (they predate
  the click → re-attribution story, `is_reattributed: true`).

## The signing (what `sign(params, kind)` does)

1. claims = `build_desc10(val, kind)` (law: session 360 B / click 388 B /
   attribution 242 B), NUL-padded to 4 bytes;
2. region: `S = os.urandom(4)`, `d0/d2/d4 = region(S, 0, 0, head=(0x2B, 0x48))`
   — the solved genuine d0 phase for request signings;
3. descriptors in `VA_ORDER = [0,9,8,4,2,7,10,5,1,6,3]`;
4. blob = `finex_mint(descs, second)` — the VM, seeded with the wall-clock
   signing second, emits header + 176-B body into one 48-word stream;
5. `Authorization: Signature signature="…"` + `Client-SDK: android5.7.0`
   header on EVERY request (its omission = 400 "unsupported sdk").

Every request is signed SEPARATELY — the server binds the blob to that
request's claims (a reused blob 500s the click).

## Regenerating the signer

After an app/lib update: `python _build_signer.py` (reads the sources in
`adj9/rev/` and the extracted `libsigner.so`, emits a fresh
`adj9_signer.py`). Verify with `python diff_test.py` — mints through both the
merged and the original stack and asserts byte-identical blobs (3/3 MATCH on
the current build).
