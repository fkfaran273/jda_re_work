## THE LAW (complete)

```
blob(304) = header(16) || body(256) || tag(32)

header  bionic rand() of the signing second (310-draw warm-up, 8 draws,
        pair-XOR, big-endian)
record  = '{ "a":  <A> ,"b": "<H>" ,"c": "<cert40>","d": "<D8>",
            "e": "<sha256('') hex-upper>" }\x00' + 0x10 * 16      (256 B)
          A  = str(u64le(nonce12[0:8])) right-justified to 20 chars
          D8 = hex-upper(nonce12[8:12]);  nonce12 = per-signing 12-B nonce
               (random on-device; the emulator's mocked RNG made it fixed)
          cert40 = the app signing-cert SHA-1 as 40 hex chars (real device)
               or 40 NUL bytes (emulator no-cert path)
          H  = sha256 with custom IV0 over 00*40 || nonce12 ||
               sha256('') hex-upper || claims
claims = the native's 98-key pool in pool order, present values bare,
         pinned "1300000" between profile (< "seq") and tail;
         activity_kind/client_sdk append when the signed map carries them
         (Java's d.sign adds both before nSign; the wire filters them)
body   = CBC-AES256(IV = header, plaintext = record);  AES-256 with the
         measured ShiftRows law (M[r][c] = M[(r+c)%4][c]) and NO final
         SubBytes (out = SR(s13) ^ K14);  keys = textbook AES-256 expansion
         of the generation seed f110fb41…654b (universal across 3.61/3.62)
tag    = HMAC-SHA256(DK37, blob[16:272])
auth   = Signature signature="<304-B UPPER HEX>",adj_signing_id="1300000",
         algorithm="adj7",headers_id="7",native_version="3.61.0"
```

Recorded constants (no generating rule — like adj8's DK38): SEED, DK37,
IV0, the claim pool.  Open question for the live test only: whether the
server recomputes H with block2 (activity_kind+client_sdk) — the funnel's

## Pure-algo status (what stands between here and `adj7_pure.py`)

Solved closed-form: header PRNG law, tag law (DK37), claims law, signing
second rules.  The **body whitening** is the open part, and it is hard in a
way adj8/adj9 were not:

- 3.67.0 (adj8) computes plain AES-256-CBC directly in native code; 5.0.0
  (adj9) computes its SPN directly.  **3.6x is the only generation whose SPN
  runs inside a bytecode VM (word-stack machine) whose program is generated
  at runtime, per signing** — there is no static S-box/round loop in the
  binary to read (a prior full stage documented this: `../adj7_work/ADJ7_MINT_FINDINGS.md`).
- Measured this session (`work/`): the engine works in a word-swapped
  (LE-per-4-B) domain; output chunks are written swap4'd (`ws1040.bin` =
  swap4(blob)); KB362 = 16 round keys, all 64 dwords read once per chunk;
  SHA-256 uses the FIPS IV (0xCC-masked in the lib); the record plaintext is
  NEVER materialized contiguously (the VM assembles chunk inputs inline);
  the VM program exists in 4 heap copies per signing, each embedding a 20-B
  and a 32-B claims commitment (+0x314 apart); the F-shaped mix of the
  sibling 5.0.0 algorithm is singular, so the adj7 body cannot be
  "decrypted" — only forward-computed.

Open items (`work/` — see SPN_FINDINGS.md / COMMIT_FINDINGS.md):
1. ~~the claims-commitment construction (c20/c32)~~ — **SOLVED 2026-10-05**
   (`commit2_hunt.py`, LAW VERIFIED on 3 mints):
   ```
   IV0 = 16ba6d02 11a298c2 82187e46 4c148c22 3a5cbc15 06519f14 97b9e370 08ec3bec
   msg = 00*40 || d666bf3444ddccca7eada76a || hex-upper(sha256(b"")) || claims
   H   = SHA-256 with custom IV=IV0 over msg (standard rounds/K/padding/feed-forward)
   c20 = LE-word-encode(H[12:32])     c32 = LE-word-encode(last block's raw vars)
   ```
   (residual: IV0's own derivation + the 12-B prefix provenance — recalibrate
   via one instrumented mint if the app changes);
2. ~~the VM container~~ — **MAPPED 2026-10-05** (`SPN_FINDINGS.md`): opcode
   dispatch at emu 0x4b8324, complete opcode stream captured (25,204 VM
   opcodes/signing, `v9_ops.txt`); per chunk: 255-iteration × 4-opcode
   key/table phase (KB362 consumed here as the UNMASKED LE view, materialized
   into VM nodes — the S-box is GENERATED at runtime inside the VM, which is
   why every static-table search fails), then 14 rounds (13 × the same
   10-opcode group + a final round with the mix skipped — AES-family shape),
